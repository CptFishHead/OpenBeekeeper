## Импринтер: подтверждено установленным байткодом

Классы: `TileImprinter`, `TileImprinter$slots$`, обработчики `tryStart` и `GeneTemplate$`.

| Слот OC | Внутренний Java | Назначение |
|---|---|---|
| 1 | 0 | Gene Template |
| 2 | 1 | Genetics Labware |
| 3 | 2 | Входная пчела |
| 4 | 3 | Обработанная пчела |

- Вход принимает принцесс и трутней; матки явно исключены в `isItemValidForSlot`.
- Каждая хромосома из шаблона заменяет и primary, и secondary. Остальные сохраняются.
- Шаблон хранит root UID в поле `species`, образцы — в `samples`. Это **не означает**,
  что вид пчелы задан самим корневым полем `species=rootBees`: ген вида находится
  среди образцов с `chromosome=0`. При валидации нельзя путать эти два понятия.
- `doStart` расходует одну входную пчелу, создаёт выход и проверяет расход Labware;
  шаблон не расходуется. Его извлечение разрешено лишь при пустом входе и отсутствии
  незавершённого выхода операции.
- Частичный шаблон допустим. Пчела помечается анализированной, если она уже была
  анализирована или шаблон полный. Профиль без SPECIES не является полным.
- Для пчёл, отличных от трутней, есть ветка риска гибели в зависимости от `isNatural`.
  Встроенный `assets/gendustry/config/tuning.cfg`: natural=0%, artificial=10%.
  В найденных override-файлах видны recipes и upgrades; сервер может иметь свои
  значения, недоступные в клиентской папке.

Открытый исходник, сопоставленный с установленным классом:
https://github.com/bdew-minecraft/gendustry/blob/mc1.12/src/net/bdew/gendustry/machines/imprinter/TileImprinter.scala

## OC: каталог и образцы

В JAR есть `DriverBeeHouse$Environment`, `ConverterItemStack$`, `ConverterIAlleles`,
`NetworkControl$class`. Специальных Gendustry-классов в списке пакетов OC не найдено.

Обычная пасека Forestry может дать компонент `bee_housing` с методами
`listAllSpecies`, `getBeeBreedingData`, `getBeeParents`, `getBeeChildren`, `getQueen`,
`getDrone`, `canBreed`. Наличие драйвера в клиенте ещё не доказывает доступ на сервере.

`listAllSpecies` проходит по `getMutations(false)` и собирает результаты мутаций,
поэтому это не полный реестр всех шаблонов/диких видов. Здесь `false` означает
отключённое перемешивание списка, а не скрытие секретных мутаций.
Преобразователь видов использует поля `uid` и `name`.

`getBeeBreedingData` возвращает поля `allele1`, `allele2`, `result`, `chance`,
`specialConditions`. Имена родителей и результата локализованы (`getAlleleName`),
а не UID. Для графа требуется однозначное сопоставление с каталогом; коллизии
имён нельзя молча разрешать выбором первого вида.

В локальном `config/opencomputers/settings.conf`, строка 608:
`allowItemStackNBTTags=false`. Строка 621: `enableInventoryDriver=false`.
На сервере драйверы/настройки могут отличаться: чтение `inventory` уже было
подтверждено пользователем. Поэтому эти значения — свидетельство о клиенте,
а не окончательный диагноз сервера. Настройки не менялись.

Стандартный разрешаемый OC NBT описан как сжатые данные, а не готовая Lua-таблица.
Текущий декодер `tag`/`nbt` покрывает лишь структурированное представление провайдера;
на установленной сборке оно ещё не подтверждено. Для зелёных узлов требуется
отдельно проверить реальный дескриптор Gene Sample.

## Локальные изменения и полнота каталога

- `scripts/Gendustry.zs` содержит изменения крафтов механизмов, в том числе
  imprinter и mutatron. Это не означает изменение алгоритма их работы.
- `scripts/MM_CyberneticBeesClient.zs` содержит карту из 37 типов для кибер-пчёл.
  Это специализированное подмножество, **не список всех пчёл сборки**.
- В `config/forestry/apiculture.cfg` значение `second.princess=0.0`, режим NORMAL,
  локальный blacklist видов пуст. Серверные значения отдельно не проверены.
- Override улучшения Gendustry предусматривают light, sealing, sky и климатические
  улучшения. Они полезны для первого цикла новой матки до получения потомства,
  пригодного для импринтера.

## Решение для проекта

Цель ограничена генами видов. Рабочий шаблон — отдельный профиль без SPECIES.
Новые матки сначала размножаются в подходящей пасеке; потомство проходит
импринтер; избыток трутней отправляется на случайное извлечение гена. Каталог
получаем из живого API и дополняем отсутствующими дикими/особенными видами.
Исполнитель остаётся выключенным до проверки серверных дескрипторов и экспорта.

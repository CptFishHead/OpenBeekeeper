# Масштабируемый сбор генов

Цель: собрать в МЭ-архиве образцы генов **всех доступных видов пчёл**.
Сбор всех вариантов остальных признаков не входит в цель. Рабочие характеристики
применяются из выбранного шаблона через генетический импринтер.
Коллекция живых видов и коллекция генов видов имеют отдельные показатели.
Без полного серверного каталога показываем «найдено N», а не «100%».
Ниже — проект исполнителя; текущий код сохраняет роли сетей, выполняет чтение
и показывает предварительную карту, но предметы не перемещает.

## Рекомендуемая схема: одна МЭ и локальные буферы

Общая МЭ-сеть хранит трутней, принцесс, маток, расходники и заполненные образцы.
Одна выбранная точка OC даёт один снимок для учёта пчёл и образцов. Снимок кэшируется
на 20 секунд между командами; такой же минимальный интервал применяется к новым
попыткам чтения. Несколько контроллеров одной сети не являются отдельными запасами.

Сундук пчеловода у транспозера — рабочий буфер партии: конкретные родители задания,
потомство и возвращаемые пчёлы. Сундук не заменяет способ точного экспорта из МЭ:
настройка интерфейса/шины и передача выбранных NBT-предметов ещё требуют проверки.
Каждый буфер закрепляется за одной станцией/заданием. Автоматический импорт не
должен забирать из него зарезервированных родителей во время работы.

Привязка: `bees setup <номер общей сети>`. В файл настроек записывается локальная
ссылка на найденный компонент, UUID не зашит в исходники. При замене устройства
нужна перепривязка. После физического объединения старых сетей предметы могут
храниться вместе; программа не объединяет сети и не перемещает их содержимое.

Для исполнителя логическое разделение остаётся: резерв родителей, активная партия,
архив образцов. В одной сети оно обеспечивается учётом и правилами выдачи, а не
тремя кабельными сетями. Отправлять в пробоотборник можно только явно выбранных
лишних трутней, не произвольные предметы общей сети. Кэш пригоден для отображения;
перед расходованием нужно повторно проверить фактический локальный инвентарь.

## Старая схема с тремя подсетями (совместимость)

| Роль | Содержимое | Политика |
|---|---|---|
| Племенная | Трутни, принцессы, матки | Резерв линий, выдача под задания |
| Перекладная | Материалы активных заданий, буферы станций | Один владелец каждого буфера |
| Архив генов | Заполненные образцы с точным NBT | Сборщик не расходует архив |

Поток: племенная -> транспорт -> пасеки/мутатроны -> племенная; излишек трутней ->
пробоотборники -> архив. Расходники подаются из основной базы через отдельный вход.
Принцессы и матки не подаются в пробоотборники. Пробоотборник расходует донора и
выбирает случайный ген: получение вида не означает получение образца гена вида.

Если сохраняется старая схема, это три физически изолированные сети. Не соединяем их общим
МЭ-кабелем. Перенос между сетями — через буферы интерфейсов и транспозеры.
Шина хранения на чужом интерфейсе может открыть весь его запас для расходования;
такой мост нельзя считать автоматически безопасным. Логические роли позднее можно
совместить в одной сети при отдельной защите резервов.

## Адреса и роли

UUID не входят в исходники и не определяют роль. При запуске перебираются все
компоненты и все грани транспозеров. МЭ определяется по методу `getItemsInNetwork`,
пасеки — по имени соседнего инвентаря. Число устройств не фиксируется.

Два МЭ-интерфейса могут смотреть в одну сеть; их нельзя считать независимыми
запасами. Номера в диагностике временные и после добавления устройств могут
измениться. Команда `setup` назначает `stock`, `transport`, `genes` и сохраняет
локальные привязки вне каталога программы. Мастер станций остаётся следующим этапом.
Адрес в локальном состоянии — лишь привязка. Замена устройства или неоднозначность
требует перепривязки; выбирать «первую» сеть для расходования нельзя.

Два транспозера также могут касаться одной пасеки. До выдачи заданий мастер
должен подтвердить уникального владельца механизма и буферы маршрутов.

## Много пасек

Модуль станции: промышленная пасека + транспозер + сундук пчеловода/рабочий буфер
с подачей из общей МЭ. Масштабирование — повторение модуля. При нехватке граней добавляется
транспозер/буфер, а не глобальные фиксированные стороны.

Планировщик распределяет задания по свободным совместимым станциям. Климат и
улучшения определяют совместимость с пчелой. Каждая станция имеет состояния
`idle -> reserved -> loading -> running -> collecting -> idle` и `blocked` с причиной.
Короткие опросы всех станций заменяют ожидание фиксированного времени одной пасеки.
После перезапуска сверяем журнал с фактическими предметами. Частичные переносы
учитываются по реальному количеству, буфер резервируется на одно задание.

Экспорт из МЭ ещё не проверен: `getItemsInNetwork` даёт чтение, но не произвольное
извлечение. Возможный драйвер: `store` -> база данных OC -> конфигурация интерфейса
или экспортной шины -> буфер -> транспозер. Точный выбор NBT проверяется на McSkill
до подключения исполнителя. Общий импорт не должен забирать назначенных родителей.

## Сохранение линий

Пасека увеличивает запас трутней, но обычно не увеличивает число принцесс.
Нельзя гарантировать резерв всех линий повторением циклов одной принцессы.
До расходования последней принцессы нужна дополнительная принцесса или проверенная
стратегия восстановления через импринтинг/репликатор и шаблоны. Один образец гена
вида ещё не является полным шаблоном. Без стратегии задание блокируется.

## Каталог и интерфейс

Пчела определяется по `individual.ident`. Образец определяется по тройке
`(root UID, chromosome, allele UID)`. В Gendustry 1.12 соответствующие NBT-поля:
`species`, `chromosome`, `allele`. Локализованная подпись, `hasTag` и NBT-хеш не
доказывают, какой именно ген хранится. Если МЭ не раскрывает данные, потребуется
провайдер сервера или чтение временно экспортированного образца.

- Зелёный узел: образец вида найден свежим чтением архива. `G` — структурированное
  NBT, `L` — точный серверный английский формат подписи и единственный совпавший UID
  из живого каталога. `L` не подтверждает NBT и не разрешает действия исполнителя.
- Голубой: живые пчёлы есть, образец не подтверждён.
- Жёлтый: выполняется задание. Серый: не подтверждено. Красный: блокировка.
- Карточка вида: родители, ограничения мутации, живой запас, образцы, задания.
- Рабочий профиль характеристик: пользовательский шаблон для импринтера,
  без требования собрать все варианты этих генов.
- Ошибка чтения даёт «неизвестно», а не «ген утрачен»; история достижений отдельно.

Целевой интерфейс — карта графа на экране OC с поиском и навигацией. Текущий `map`
лишь цветной текстовый просмотр и демонстрационная ветвь, без интерактивного графа.
Серверный каталог должен поддерживать несколько рецептов одного вида и ограничения.

## Следующая проверка в игре

Подключить адаптер к одной точке общей МЭ. Команда `me` перечислит точки чтения;
`setup <номер>` сохранит общую сеть. Оставить сундук пчеловода у транспозера.
Затем на отдельном тестовом предмете проверить экспорт
одного точного NBT-варианта и возврат. Только после этого реализовывать исполнитель.

## Импринтер и рабочий профиль

Слоты установленного Gendustry проверены по байткоду: 1 — шаблон, 2 — лабораторные
наборы, 3 — входная принцесса/трутень, 4 — обработанный выход. Преобразование
Java-индексов 0–3 в слоты OC 1–4 обязательно. Шаблон остаётся в машине;
его не нужно заново подавать на каждую пчелу. Драйвер импорта/экспорта не должен
извлекать шаблон как обычную продукцию.

Общий профиль содержит выбранные рабочие гены: день/ночь (`NEVER_SLEEPS`), дождь,
работа под землёй, плодовитость и продолжительность жизни. Настройки выбирает игрок.
Хромосома вида (`SPECIES`, 0) в таком шаблоне **запрещена**: иначе все линии будут
превращаться в вид из шаблона. Цветы и эффекты сохраняются, пока не выбран отдельный
профиль; климат и биом не становятся автоматически подходящими от дождя/ночи.

Импринтер записывает содержащиеся в шаблоне признаки в обе копии генома, остальные
оставляет прежними. Полный шаблон для этого не требуется. Матки не принимаются.
Новая матка из мутатрона сначала проходит один цикл в совместимой пасеке, затем
полученные принцесса и трутень обрабатываются по очереди и образуют рабочую линию.
Для первого цикла можно использовать климат/ночь/дождь улучшения пасеки.

Состояния: `validate_profile -> reserve -> imprint_princess -> imprint_drone ->
verify_genome -> ready`. Проверяется неизменность UID вида и обе копии нужных генов.
Нечитаемый геном/шаблон означает «проверка невозможна», а не успех. Частичный
шаблон не гарантирует, что неанализированная пчела станет анализированной, поэтому
для проверки может понадобиться отдельный анализатор.

Для принцесс существует настраиваемый риск гибели; для трутней эта ветка проверки
в коде пропускается. Встроенные параметры JAR дают 0% для natural и 10% для
artificial, но это не подтверждённые настройки сервера. Последнюю принцессу нельзя
подавать автоматически без стратегии восстановления и подтверждённой политики.

Подробности установленной сборки: [mcskill-audit.md](mcskill-audit.md).

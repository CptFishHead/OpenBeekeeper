# Масштабируемый сбор генов

Цель: собрать в МЭ-архиве образцы видов пчёл и остальных аллелей, доступных на
сервере. Коллекция живых видов и коллекция генов имеют отдельные показатели.
Без полного серверного каталога показываем «найдено N», а не «100%».
Ниже — проект исполнителя; текущий код выполняет только чтение и предварительную карту.

## Три роли МЭ

| Роль | Содержимое | Политика |
|---|---|---|
| Племенная | Трутни, принцессы, матки | Резерв линий, выдача под задания |
| Перекладная | Материалы активных заданий, буферы станций | Один владелец каждого буфера |
| Архив генов | Заполненные образцы с точным NBT | Сборщик не расходует архив |

Поток: племенная -> транспорт -> пасеки/мутатроны -> племенная; излишек трутней ->
пробоотборники -> архив. Расходники подаются из основной базы через отдельный вход.
Принцессы и матки не подаются в пробоотборники. Пробоотборник расходует донора и
выбирает случайный ген: получение вида не означает получение образца гена вида.

Начальный вариант — три физически изолированные сети. Не соединяем их общим
МЭ-кабелем. Перенос между сетями — через буферы интерфейсов и транспозеры.
Шина хранения на чужом интерфейсе может открыть весь его запас для расходования;
такой мост нельзя считать автоматически безопасным. Логические роли позднее можно
совместить в одной сети при отдельной защите резервов.

## Адреса и роли

UUID не входят в исходники и не определяют роль. При запуске перебираются все
компоненты и все грани транспозеров. МЭ определяется по методу `getItemsInNetwork`,
пасеки — по имени соседнего инвентаря. Число устройств не фиксируется.

Два МЭ-интерфейса могут смотреть в одну сеть; их нельзя считать независимыми
запасами. Номера в диагностике временные и после добавления устройств могут
измениться. Будущий мастер настройки назначает `stock`, `transport`, `genes`.
Адрес в локальном состоянии — лишь привязка. Замена устройства или неоднозначность
требует перепривязки; выбирать «первую» сеть для расходования нельзя.

Два транспозера также могут касаться одной пасеки. До выдачи заданий мастер
должен подтвердить уникального владельца механизма и буферы маршрутов.

## Много пасек

Модуль станции: промышленная пасека + транспозер + доступный ему буфер интерфейса
перекладной сети. Масштабирование — повторение модуля. При нехватке граней добавляется
транспозер/буфер, а не глобальные фиксированные стороны.

Планировщик распределяет задания по свободным совместимым станциям. Климат и
улучшения определяют совместимость с пчелой. Каждая станция имеет состояния
`idle -> reserved -> loading -> running -> collecting -> idle` и `blocked` с причиной.
Короткие опросы всех станций заменяют ожидание фиксированного времени одной пасеки.
После перезапуска сверяем журнал с фактическими предметами. Частичные переносы
учитываются по реальному количеству, буфер резервируется на одно задание.

Экспорт из МЭ ещё не проверен: `getItemsInNetwork` даёт чтение, но не произвольное
извлечение. Возможный драйвер: `store` -> база данных OC -> конфигурация интерфейса
или экспортной шины -> буфер -> транспозер. Точный выбор NBT проверяется на McSkill
до подключения исполнителя. Общий импорт не должен забирать назначенных родителей.

## Сохранение линий

Пасека увеличивает запас трутней, но обычно не увеличивает число принцесс.
Нельзя гарантировать резерв всех линий повторением циклов одной принцессы.
До расходования последней принцессы нужна дополнительная принцесса или проверенная
стратегия восстановления через импринтинг/репликатор и шаблоны. Один образец гена
вида ещё не является полным шаблоном. Без стратегии задание блокируется.

## Каталог и интерфейс

Пчела определяется по `individual.ident`. Образец определяется по тройке
`(root UID, chromosome, allele UID)`. В Gendustry 1.12 соответствующие NBT-поля:
`species`, `chromosome`, `allele`. Локализованная подпись, `hasTag` и NBT-хеш не
доказывают, какой именно ген хранится. Если МЭ не раскрывает данные, потребуется
провайдер сервера или чтение временно экспортированного образца.

- Зелёный узел: образец гена вида подтверждён свежим чтением назначенного архива.
- Голубой: живые пчёлы есть, образец не подтверждён.
- Жёлтый: выполняется задание. Серый: не подтверждено. Красный: блокировка.
- Карточка вида: родители, ограничения мутации, живой запас, образцы, задания.
- Отдельный каталог остальных генов: скорость, плодовитость, эффекты и т. д.
- Ошибка чтения даёт «неизвестно», а не «ген утрачен»; история достижений отдельно.

Целевой интерфейс — карта графа на экране OC с поиском и навигацией. Текущий `map`
лишь цветной текстовый просмотр и демонстрационная ветвь, без интерактивного графа.
Серверный каталог должен поддерживать несколько рецептов одного вида и ограничения.

## Следующая проверка в игре

Подключить адаптер к МЭ-интерфейсу каждой подсети, сохранив сети изолированными.
Команда `me` перечислит точки чтения. Положить пчелу и заполненный Gene Sample в
маленькую тестовую сеть; `probe <номер>` покажет их поля. Затем проверить экспорт
одного точного NBT-варианта и возврат. Только после этого реализовывать исполнитель.

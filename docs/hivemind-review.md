# Обзор HiveMind

Источник: https://github.com/Aedial/HiveMind

Проверен `main.lua`, Git blob `63c2a1e32ea0b9be42593bc2670ca86bb3b36bc6`.
Обзор выполнен 25 октября 2026 года. Это статический просмотр; запуска на McSkill не было.

## Как задуман процесс

В программе есть встроенная база родителей для видов нескольких модов. Игрок
выбирает целевой вид, планировщик строит дерево зависимостей. Основная линия
принцессы называется golden path; боковые ветви нужны для получения трутней.
Предусмотрены накопление трутней, загрузка мутатрона, перенос матки в промышленную
пасеку и сбор потомства. В интерфейсе можно посмотреть план и состояние работы.

README также описывает Mechanical User и Beebee gun с Assassin Queen для
ускоренного получения потомства. Это оборудование не входит в нашу проверенную установку.

## Что мешает прямому использованию

- На старте жёстко требуется компонент `inventory_controller`. Наша установка
  использует `transposer`. В исходнике перенос вызывается через
  `inv_controller.transferItem(...)`; нельзя считать это совместимым без адаптации.
- В `scanInventory()` выбирается `stack.name or stack.label`, после чего из строки
  пытаются получить вид. У наших пчёл `name` имеет вид `forestry:bee_princess_ge`:
  это тип предмета, а не Cultivated или Diligent. Вид следует читать через
  `individual.ident`, когда этот провайдер доступен.
- `useGendustryAPI(parent1, parent2, target)` перечисляет возможные методы,
  необязательно читает прогресс/состояние и возвращает успех, если нашёл компонент
  с `mutatron` в имени. Параметр `target` не используется для выбора мутации.
- В список возможных Gendustry-компонентов включён обычный `transposer`, поэтому
  сообщение об обнаруженной интеграции само по себе ничего не доказывает.
- В `executeSingleBreedingStep()` есть ожидание заданного времени пасеки. Это
  не гарантирует завершение при другом гене продолжительности жизни или улучшениях.
- Встроенная база охватывает другую комбинацию модов. Наличие записей не означает,
  что соответствующие виды и рецепты существуют или доступны в McSkill.

## Что переносим как идею

Планирование от цели, отдельное накопление трутней, каталог линий и видимый статус
полезны. Реализация OpenBeekeeper должна использовать проверенные методы транспозера,
проверять фактическое потомство и сохранять состояние для восстановления после остановки.

Обычный мутатрон сам выбирает доступный результат. Для пары с несколькими мутациями
планировщику нужны повторные попытки и запасы родителей. Собрать все виды можно
обещать только после проверки серверной базы рецептов и ограничений.

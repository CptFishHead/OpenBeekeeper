# Климатические зоны и очередь 0.11.0

## Перенастройка установки

Сначала Ctrl+C для остановки старого исполнителя. Затем:

```sh
bees update
bees bind
bees zones breeding native
bees zones
bees auto check
bees auto
```

`bind` нужен после добавления новых модулей. `zones breeding native` явно
назначает все пасеки без эмуляторов в роль размножения. Количество модулей и пасек произвольное; убедитесь, что биомные группы имеют
установленные эмуляторы, прежде чем применять это массовое назначение.
Никакие улучшения команда не вставляет и не извлекает.

Отсутствие эмулятора само по себе не назначает роль. Без явной настройки такая
пасека остаётся unassigned и не принимает новые задания. Пасеки с распознанным
эмулятором автоматически получают роль incubator. Можно иметь по четыре или
любое другое число пасек одной зоны; адреса и количество не зашиты в код.

Пара после анализатора/импринтера идёт только в breeding. Готовая матка — через
анализатор только в incubator с подходящими температурой и влажностью. Если нет
свободной подходящей зоны, матка остаётся в МЭ с точной записью NBT и ждёт,
а остальные задания подготовки продолжают обслуживаться. Ёмкость очереди конечна.
Один вид может одновременно размножаться на нескольких пасеках, если есть пары.

## Как вычисляется климат

Улучшения читаются из OC-слотов 3–6 пасеки. Поддержаны Plains, Jungle, Desert,
Winter, Ocean и Hell Emulation Upgrade, Heater, Cooler, Humidifier и Dryer.
Число модификаторов учитывается: по 0,25 за предмет, согласно клиентской конфигурации.
Для Hell температура остаётся HELLISH, как в `TileApiary.getTemperature`.

| Эмулятор | Температура | Влажность |
|---|---|---|
| Plains | NORMAL | NORMAL |
| Jungle | WARM | DAMP |
| Desert | HOT | ARID |
| Winter (taiga) | COLD | NORMAL |
| Ocean | NORMAL | NORMAL |
| Hell | HELLISH | ARID |
| Jungle + 1 Cooler | NORMAL | DAMP |
| Winter + 1 Cooler | ICY | NORMAL |

Таблица — базовые категории без дополнительных модификаторов и высотного
охлаждения. При пограничных значениях высота и серверные изменения могут дать
другую категорию. По GUI пасеки можно явно задать её фактический климат:

```sh
bees zones climate 17 HOT ARID
```

Номер 17 — пример: актуальные номера показывает `bees zones`. Он не сохраняется
как постоянный идентификатор; настройки привязаны к адресу транспозера и грани.
Команда также назначает роль incubator. Ручное значение действует только пока
сигнатура установленных улучшений не поменялась.

Индивидуальные роли:

```sh
bees zones role 1 breeding
bees zones role 17 incubator
bees zones role 18 off
bees zones clear 18
```

Установка эмулятора распознаётся автоматически; программа его не заменяет.
Из входных слотов пасеки и слотов улучшений транспозер в этой сборке извлекать
не может. Уже застрявшую в неверной зоне матку нужно вынуть через GUI и вернуть
в МЭ, либо вручную исправить среду её текущей пасеки. Автоматического переноса
уже загруженных маток между пасеками эта версия не обещает.

## Требования маток

После анализатора UID вида и активные/неактивные хромосомы раскрываются драйвером.
Но установленный OC `ConverterIAlleles` передаёт для вида только name/uid, без
предпочтительных температуры/влажности. Поэтому используются проверенные
предпочтительные категории из клиента, а не выдуманные поля дескриптора.

`src/climate-data.json` содержит 175 записей из Forestry 5.8.2.422, Binnie's Mods
2.5.1.203 и Gendustry 1.6.5.8. Значения извлечены из `setSpeciesProperties`
анонимных классов BeeDefinition/ExtraBeeDefinition через javap, с проверенными
NORMAL/NORMAL по умолчанию в AlleleSpecies, и конфигураций bees_color/bees_patreon.
Это справочник клиентских предпочтений, не утверждение о полном реестре сервера.
Для серверного отличия либо неизвестного вида:

```sh
bees zones species forestry.speciesSinister HELLISH ARID
```

UID в примере нужно заменить фактическим. Неизвестная потребность блокирует
только загрузку данной матки, а не подменяется NORMAL/NORMAL. Маршрутизация
инкубации выбирает точные предпочтительные категории и консервативно не
полагается на нераскрытые допуски. Цветы, ночь и другие условия остаются
отдельными требованиями. По последнему разрешению игрока все условные рецепты включены. Условия выводятся явно; OC не подтверждает их выполнение. На сервере мутатрон может быть настроен игнорировать требования, учитывать их или запрещать отдельные виды. Эмуляция пасеки влияет на её климат и сама по себе не меняет условия стоящего отдельно мутатрона.

## Почему раньше было мало работающих пасек

До 0.10.0 существовали одна цепочка подготовки родителей и блокировка всего
вида, пока любая его матка работала. Теперь есть несколько сохраняемых цепочек:
анализатор принимает очередь в OC-слоты 3–8; импринтер обрабатывает готовый выход,
пока анализатор занят следующим заданием. На одного анализатора планируется до
шести цепочек, с ограничением доступными свободными ячейками базы OC.
На очередь шести пар нужно до 13 свободных ячеек; при меньшем количестве
программа уменьшает подготовительную очередь, а не переписывает чужие записи.

Разные особи одинакового активного вида могут размножаться параллельно. При
выборе учитываются зарезервированные родители и ожидаемые трутни уже запущенных
циклов. Прогноз не выдаётся за фактический склад: после реального выхода цель
проверяется заново. Известная плодовитость берётся из обработанного генома;
без неё применяется оценка 4, которая уточняется реальными возвратами.

Для сохранения генетической идентичности два одновременно анализируемых
задания одного UID и типа (например, два разных генотипа трутня одного вида)
не смешиваются: их выход без NBT до анализа нельзя надёжно различить.
Машина допускает стеки до своего лимита, но племенные задания этой версии
подают по одной требуемой особи на спаривание; массовый прогон всего склада
целыми стеками отдельно не запускается. Все выходные слоты забираются целиком.

В тестовой модели одновременно загружены все 16 пасек размножения и все шесть
приёмных слотов анализатора. На сервере занятость зависит от числа реальных пар,
скорости обработки, длительности маток и наличия подходящих зон. Цель программы
— получать нужное потомство, а не держать каждую пасеку занятой любой ценой.

# Общий автоцикл 0.11.7

## Запуск

```sh
bees update
bees bind
bees zones breeding native
bees zones
bees auto check
bees auto
```

Если старый `bees run` ещё работает, сначала остановить его через Ctrl+C. Новая
команда `run` является синонимом `auto`. Не запускать два исполнителя одновременно.
Существующие привязки `bees bind` и настройка общей МЭ сохраняются.

Количество пасек и механизмов не фиксировано. После изменения схемы остановить
исполнитель, выполнить `bees bind`, назначить роли через `bees zones` и проверить
`bees auto check`. Без мутатрона отключается вывод новых видов, без пробоотборника —
пробоотбор; без анализатора не создаются новые задания подготовки пчёл.
Без импринтера недоступны обычное разведение и подготовка доноров, но мутации работают.
Доступные ветки продолжают работу. Для новых мутаций нужна хотя бы одна
инкубационная зона; неизвестный климат результата оставляет матку в очереди.
Удаление механизма с незавершённым заданием не отменяет его автоматически.
База OC нужна для точных описаний; очередь учитывает её свободную ёмкость.
Перед стартом запросы и рабочие буферы интерфейсов должны быть пустыми.
Ресурсные слоты механизмов не очищаются. Чужая незавершённая работа не присваивается.

Настройка перед запуском, без фиксированного числа пасек:

```sh
bees auto config
bees auto config batch 64
bees auto config queue auto
bees auto config mutations on
bees auto config sampling on
bees auto check
```

`batch` — 1–64 трутня одного точного NBT за анализ, принцессы/матки идут по одной.
`queue auto` рассчитывает ёмкость по устройствам и свободной базе; `queue N` задаёт
верхнюю границу 1–128. Опции сохраняются отдельно от программы.
Роли breeding/incubator/off задаются отдельно через `bees zones role`.
Пасеки breeding также принимают анализированных маток при совпадении климата;
специальные incubator не обязательны. Нативный климат нельзя определить только
по отсутствию эмулятора. Если он подтверждён как NORMAL/NORMAL, команда
`bees zones breeding native NORMAL NORMAL` назначает все нативные пасеки для
разведения и записывает этот климат. Иной климат задаётся теми же двумя аргументами.
Команда `bees zones climate <номер> <TEMP> <HUMIDITY>` сохраняет явно заданную роль.
Пасеки off и unassigned для загрузки маток не используются.

В импринтере остаётся пользовательский шаблон без вида и эффекта; его состав
подтверждён игроком. Программа его не меняет. Весь код встроен в основной Lua-файл,
загрузка нового отдельного модуля на игровой компьютер не требуется.

## Порядок работы

1. Выбрать матку либо родителей по текущему снимку МЭ.
2. Неанализированных родителей провести через анализатор, трутней — партиями; для обычного разведения затем каждого родителя через импринтер. Для мутатрона импринтинг родителей пропускается.
3. В пасеку/мутатрон загружать только эти точные обработанные экземпляры.
4. Дождаться реального выхода, вернуть его в МЭ полными слотами, проверить вид.
5. Перестроить следующий шаг по фактическому складу, а не ожидаемому результату.

Между машинами пчёлы возвращаются через общую МЭ, но не теряют свою идентичность:
транспозер копирует точный стек/NBT выходной пчелы в принадлежащую заданию ячейку
базы. Следующий интерфейс запрашивает эту запись. Перед переносом выполняется
`compareStackToDatabase(..., true)`, включая NBT. Для первоначального выбора
применяются name/label и затем проверяются реальный UID/тип. До первой обработки
недоступного родителя можно перевыбрать с повторной проверкой анализа; после обработки
выбор по одному названию не используется. UID вида проверяется после анализатора
и импринтера. Неожиданная смена вида останавливает поток с сохранением выхода.

Общий снимок МЭ запрашивается не чаще раза в 20 секунд и содержит пчёл/образцы.
`store` отдельно копирует описание выбранного предмета/расходника. Локальные
инвентари проверяются между обновлениями МЭ. Номера/порядок UUID не определяют
назначение: используются сохранённые связи транспозера, интерфейса и грани.

Подготовка ведётся независимыми заданиями. Шесть входов анализатора не ограничивают
размер всей очереди. Однородный стек трутней анализируется целиком; уже анализированные
особи повторно не занимают анализатор. Импринтер обрабатывает особей по одной,
согласно механике Gendustry. Если другие задания ссылались на тот же сырой стек,
их ссылки обновляются только после точного сравнения реального входа с базой.

Диспетчер по кругу обслуживает инкубацию, мутации, размножение и пробоотбор;
размножение получает два прохода, остальные ветки — по одному. Пустые очереди
пропускаются. Мутации не ждут окончания всего размножения; последняя принцесса
линии не отдаётся в новую мутацию, пока запас её трутней ниже 16. Рулетка
сохраняет фактический результат, после чего следующая попытка может готовиться
независимо от инкубации побочного вида.

У каждого интерфейса один владелец запроса. Запросы разных интерфейсов ожидаются
параллельно: ожидание доставки не вызывает 15-секундного сна общего цикла.
Возврат выходов через интерфейс откладывается, пока он обслуживает запрос.
Снимок МЭ раз в 20 секунд сверяет локальный учёт фактических загрузок/возвратов;
завершение операции больше не блокирует планирование до следующего снимка.

Пасеки используются по доступным ролям и парам, без ограничения числом 16 или 21.
Среди свободных пасек приоритет получают Light/Seal Upgrade. Новая матка после
мутатрона проходит анализатор и идёт только в совместимую инкубационную зону.
Проверяются температура/влажность по справочнику и явным поправкам; питание,
цветы и остальные условия среды обеспечивает игрок. Все её последующие родители
проходят подготовку. Постоянная занятость каждой пасеки при нехватке пар или
производительности импринтера не гарантируется.

## Запас, образцы и потери

- Постоянная цель — 16 трутня каждого вида в МЭ.
- Если образец уже собран, но живых пчёл вида в МЭ больше нет, доступный рецепт
  мутатрона снова допускается для восстановления линии. Образец сохраняется;
  после восстановления размножение доводит запас до 16 без повторного пробоотбора.
  Живые матки и уже запущенные задания восстановления исключают дублирование.
- Если образец вида ещё не наблюдается, размножение готовит до 54 трутней:
  16 постоянного запаса плюс 38 потенциальных доноров. Последний вывод слота может
  превысить эту цифру и не обрезается.
- Пробоотборник получает по одному излишнему трутню, предварительно прошедшему
  анализатор и импринтер. Ниже запаса 16 донора не выбирают.
- Сообщённый игроком шанс нужного гена — 7,7% на трутня. 38 независимых попыток
  дают вероятность хотя бы одного успеха не ниже 95%, но не гарантию. После
  неудач размножение и пробоотбор продолжаются, пока есть родители и ресурсы.
- Любой образец сохраняется. Ген скорости/эффекта не засчитывается как вид.
- `G` — структурное подтверждение вида образца; `L` — уникальное совпадение
  серверного названия образца. Оба прекращают дальнейший пробоотбор этого вида,
  но L не является NBT-подтверждением и не используется для выбора генов шаблона.

Обычный мутатрон не умеет выбирать желаемый вид через установленный OC-драйвер.
Программа выбирает доступную пару из серверного рецепта, включая условные, затем
проверяет реальный UID выходной матки. Побочный вид сохраняется и размножается;
цель не засчитывается автоматически. Между доступными ветками действует обход
по кругу, чтобы неудачи одного рецепта не исключали остальные навсегда. Проценты
каталога естественных мутаций не трактуются как веса выбора обычного мутатрона.

По разрешению игрока условные рецепты включены и в `plan`, и в `auto`. Подписи требований показываются, но не считаются автоматически выполненными. Проверку доступности фактически выполняет серверный мутатрон согласно своим overrides; отдельная эмуляция пасеки эти правила не подменяет. Для существующих пчёл
условия получения вида не мешают обычному разведению, если сама пасека работает.
Продвинутый мутатрон в качестве автоматического селектора не поддерживается.

Для восстановления линии без принцессы программа пробует скрещивание имеющегося
трутня с принцессой другой линии в обычной пасеке. Если нет трутня при имеющейся
принцессе, используется трутень другой линии. Наследование случайно: учитывается
только реальное потомство. По разрешению игрока допускается использование
последнего трутня при восстановлении линии и последней принцессы в мутации,
когда исходный вид представлен трутнями. Это может привести к утрате части пчёл.
Запас 16 защищён от пробоотбора; для размножения/мутации он может временно снижаться.
Новые поколения перед следующим спариванием снова проходят обе машины.

Genetic Waste из импринтера/мутатрона означает потерю, а не успешную обработку.
Отход возвращается в МЭ, задание закрывается, следующая попытка планируется из
остатка. Настройки сервера могут отличаться от клиентских вероятностей гибели.
Отсутствие какого-либо выхода не выдаётся за успех: поток ждёт машину и сообщает
о нехватке питания/жидкости или зависшей операции. Внутреннюю работу машины без
доступного API нельзя безопасно отличить от исчезновения входа вручную.

## Ресурсы

Жидкий мёд и мутаген подаются пассивно внешней системой. Анализатор расходует
100 мБ мёда на операцию анализа неанализированного стека; уже анализированная особь всё равно
проходит машину, но ей по коду мода мёд не требуется. Проверка бака до загрузки
консервативно ожидает минимум 100 мБ. Электропитание/цветы/условия пасек также
обеспечиваются установкой, программа не меняет мир.

Пустые образцы и Genetics Labware пополняются из общей МЭ партиями до 16, когда
ресурсный слот пуст. Если расходника нет, программа сообщает WAIT и продолжает
обслуживать уже загруженные пасеки. Автокрафт расходников пока не заказывается:
можно обеспечить пассивное пополнение в общей сети.

## Состояние и восстановление

`Ctrl+C` снимает собственный запрос интерфейса, но не пытается извлечь уже
загруженных входных пчёл. Они остаются в машине. Продолжение:

```sh
bees auto status
bees auto
```

Основное состояние: `/home/.openbeekeeper-data/automation`, резерв — `.bak`,
проверенный новый журнал — `.new`. При запуске сначала очищается незавершённый
собственный запрос; активные записи базы сохраняются. Состояние намерения
переноса записывается до физического действия: после сбоя запускающий вход не
отправляется повторно вслепую. При неопределённом результате поток может ждать
проверки машины вместо дублирующей загрузки.

Если точный предмет не поступил за 15 секунд, снимается собственный запрос
интерфейса и задание ждёт повторной попытки минимум 20 секунд. Если ни один вход
не был загружен или вооружён, резерв машины освобождается для других заданий.
Частично загруженная машина остаётся закреплённой за своим заданием. Остальные задания
и пасеки продолжают обслуживаться. Загруженные входы и точные ссылки сохраняются;
возвращать произвольную пчелу того же вида вместо выбранной программа не будет.
Проверить наличие пчелы, её NBT и снабжение интерфейса всё равно необходимо.

### Намеренный старт заново

Если вручную убрать из МЭ выбранных пчёл, сохранённое задание всё ещё запрашивает
тот же точный NBT. Ошибка `Exact item not delivered within 15 seconds` теперь
показывает UID/тип особи. Причиной также могут быть снабжение интерфейса или
изменившийся NBT; одно сообщение не доказывает исчезновение вида.

Для намеренного перепланирования после изменения состава склада сначала
остановить все исполнители через `Ctrl+C`, проверить состояние и выполнить:

```sh
bees auto status
bees auto reset
bees auto
```

`bees run reset` — тот же одноразовый сброс. Сам сброс не запускает автоцикл,
не запрашивает полный склад МЭ. Он сохраняет точные прежние
`automation`, `.new` и `.bak` в `automation-reset-N.main/.new/.bak` вместе с
индексом `automation-reset-N.index`. Конфигурации запросов привязанных интерфейсов
дополнительно сохраняются в `automation-reset-N.interfaces`, затем очищаются
все девять запросных слотов каждого привязанного интерфейса. Старые leases и
запросы расходников отменяются. Буферы автоматически возвращаются в МЭ; если
сеть не принимает предметы, сброс ждёт до 15 секунд и сохраняет журнал для
повторной попытки. Непривязанные интерфейсы не изменяются. Затем сброс возвращает все выходные
слоты пасек, анализаторов, импринтеров, пробоотборников и мутатронов через их
интерфейсы в МЭ. Частичные переносы повторяются; при блокировке сети журнал
сохраняется для повторного `bees auto reset`. Входы и ресурсные слоты не извлекаются.
После принятия выходов сетью сброс очищает только выделенные журналом
ячейки OC-базы и создаёт пустой журнал. Привязки модулей, климатические зоны,
роли МЭ, пользовательские записи базы, шаблон, улучшения и расходники сохраняются.
Следующий запуск читает актуальную МЭ и строит новый план.

Сброс разрешён для очереди, у которой не было загруженных/вооружённых входов,
например после тайм-аута доставки первой особи. Он **отказывается** при активном
задании пасеки, внутренней работе машины, загруженном или вооружённом входе,
предмете во входном/рабочем слоте или неосвобождающемся буфере, неусыновлённом старом задании пасеки.
Пустого видимого входа недостаточно: пчела может уже находиться внутри машины.
При отказе продолжить существующее задание через `bees auto` либо выяснить
состояние указанной машины; не удалять журнал для обхода проверки.

Если входные пчёлы уже вручную убраны **из всех механизмов**, а внутренние
операции завершены или отменены, используйте `bees auto reset empty`. Это явное
подтверждение ручной очистки: старые отметки загруженных входов и заданий пасек
больше не блокируют сброс. Физические слоты, буферы, запросы интерфейсов и
принадлежность записей базы проверяются по-прежнему. Команда не извлекает пчёл
и не отменяет внутреннюю обработку механизмов. Подтверждение сохраняется в
журнале сброса, поэтому после прерывания достаточно повторить `bees auto reset`.

Намерение сброса сохраняется до очистки базы. Если сброс прерван, обычный запуск
блокируется до повторного `bees auto reset`. Неопределённая очистка непустой
ячейки блокируется, чтобы не стереть запись, созданную после сбоя: сначала
проверить и сохранить её вручную. Повторный завершённый сброс не очищает заново
старые ячейки; архивы остаются, а основной и резервный журналы содержат пустое
состояние без возможности воскресить старую очередь.

Незавершённые задания пасек 0.8.x принимаются под обслуживание. Частично загруженный
старый трутень сохраняется, но к нему не добавляют необработанную принцессу.
Такая пасека остаётся занятой до ручного освобождения; другие пасеки продолжают
работу. Новые задания всегда используют обязательный порядок обработки.

Не менять пчёл, записи выделенных ячеек базы и запросы интерфейсов во время
работы. Повреждённый журнал не заменяется автоматически старым состоянием,
которое могло бы повторить загрузку. При замене блоков сначала сверить старые
задания и только затем перепривязывать схему. Компьютер должен оставаться
запитанным, а чанки — загруженными. Автозапуск после перезагрузки не изменяется.

Никакое IDLE-сообщение не означает сбор абсолютно всех видов: живой каталог
содержит результаты мутаций, может не включать дикие виды, и не подтверждает выполнение всех условий. Недоступные родители потребуют внешнего источника.

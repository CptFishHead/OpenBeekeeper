# Установка и обслуживание OpenBeekeeper

Нужны установленная на диск OpenOS, интернет-карта и доступ сервера к
`raw.githubusercontent.com`. Дополнительные библиотеки и карта данных не нужны.

В командной строке OpenOS (`/home #`, а не `lua>`) выполните одну команду:

```sh
wget -fq https://raw.githubusercontent.com/CptFishHead/OpenBeekeeper/main/install.lua /home/beekeeper-setup.lua && lua /home/beekeeper-setup.lua
```

Установщик загружает необходимые файлы приложения из одной зафиксированной версии
репозитория. Проверяет размер, контрольную сумму Adler-32 и синтаксис Lua до замены
файлов. Adler-32 обнаруживает ошибки записи/загрузки; это не криптографическая подпись.
Перед заменой сохраняет резервную копию, после записи проверяет результат.
При сбое замен прежние файлы восстанавливаются. Если восстановление тоже не удалось,
журнал остаётся для повторной попытки при следующей установке.
Начиная с 0.3.2 запрос манифеста использует меняющийся параметр для обхода старого
ответа кэша. Загруженные файлы по-прежнему привязаны к одному коммиту.

Программа не добавляется в автозапуск и компьютер не перезагружается.
Установщик не управляет пасеками и МЭ. Диагностические команды выполняют только
чтение; команда `bees bind` временно запрашивает булыжник в МЭ-интерфейсы.
Запускайте одну установку/обновление за раз.

## Короткие команды после установки

| Команда | Действие |
|---|---|
| `bees check` | Проверка установленных файлов, сумм и синтаксиса, без Интернета |
| `bees update` | Скачать актуальную версию; исправные файлы текущей версии повторно не качаются |
| `bees reinstall` | Заново скачать и проверить весь комплект, даже если версия не изменилась |
| `bees repair` | То же, что reinstall |
| `bees rollback` | Вернуть файлы из резервной копии перед последней установкой |
| `bees scan` | Устройства и соседние инвентари |
| `bees catalog` | Каталог через обычную пасеку Forestry с адаптером |
| `bees me` | Точки чтения МЭ, отдельно экспортные шины X и базы данных D |
| `bees setup 1` | Выбрать общую МЭ-сеть №1 для пчёл и образцов; актуальный номер взять из me |
| `bees roles` | Проверить сохранённые роли и доступность компонентов |
| `bees probe 1` | Примеры данных пчёл/образцов из выбранной МЭ-точки |
| `bees probe genes` | Примеры образцов из сохранённой архивной сети |
| `bees probe network` | Примеры предметов из сохранённой общей сети |
| `bees map` | Цветной предварительный просмотр коллекции |
| `bees owned` | Только найденные виды пчёл и образцы, без отсутствующих видов |
| `bees bind` | Связать интерфейсы с транспозерами, запросив по очереди один булыжник |
| `bees bind-reset` | Снять оставшийся после прерывания запрос привязки |
| `bees modules` | Показать сохранённые связи модулей |
| `bees plan` | Количества родителей, кандидаты для образцов и следующие мутации; только чтение |

Перед `bind` нужны пустые запросы/буферы интерфейсов, хотя бы один булыжник в общей
МЭ и свободная ячейка любой базы OC. Пчёлы и шаблон не перемещаются.
Подробности: [привязка модулей](docs/module-binding.md).

`check` проверяет установку, а не правильность подключения механизмов. Для устройств
используется отдельная команда `scan`. Номера МЭ-точек из `me` временные.
В 0.5.0 запросы содержимого МЭ имеют общий интервал **20 секунд**, а успешные снимки
пчёл и образцов кэшируются на это время между запусками команд. Повторная команда
на свежем снимке не вызывает МЭ и не ждёт. Одной сети достаточно: сундук пчеловода
используется как местный буфер для будущего исполнителя. Старый формат трёх ролей
сохранён; переход на общую сеть — `bees setup <номер>` после физического объединения.

## Где находятся файлы

- `/usr/bin/bees.lua` — команда запуска.
- `/home/.openbeekeeper/` — управляемые файлы приложения и манифест.
- `/home/.openbeekeeper-data/` — выделенное место для настроек и коллекции будущего
  исполнителя; установщик не удаляет и не заменяет содержимое этого каталога.
- `/home/.openbeekeeper-install/` — загрузки и журнал установки на диске, не в RAM-диске.
- `/home/openbeekeeper-backup/backup-...` — резервные копии заменённых файлов.
- `/home/beekeeper-setup.lua` — исходная точка восстановления, загруженная первой командой.

Старые диагностические `beekeeper-fix.lua` и подобные файлы не трогаются.
Переустановка не удаляет пользовательские данные. Откат после самой первой установки
удаляет созданные управляемые файлы приложения, потому что предыдущей версии не было;
каталог пользовательских данных остаётся. Откат возвращает одну сохранённую версию,
не переключает версии туда и обратно.

## Если команда bees повреждена

Запустите независимую точку восстановления:

```sh
lua /home/beekeeper-setup.lua reinstall
```

Если отсутствует и она, повторите первую команду установки. При наличии незавершённого
журнала сначала восстанавливаются предыдущие файлы, затем выполняется новая загрузка.
Если новая загрузка недоступна, восстановленная предыдущая версия остаётся на месте.
Не удаляйте каталог резервной копии, указанный при ошибке восстановления.

## Выпуск новой версии для разработчика

1. Изменить `VERSION`, код и документацию; выполнить тесты.
2. Опубликовать коммит с файлами `openbeekeeper.lua`, `install.lua`, `bees.lua`,
   `VERSION`, `README.md`.
3. Выполнить `python tools/build_manifest.py <SHA-коммита>`.
4. Отдельным коммитом опубликовать `package.manifest`.

Генератор считает суммы именно Git-объектов, чтобы переводы строк Windows не
исказили проверку. Манифест указывает на неизменяемый коммит: обновление ветки
во время скачивания не смешает версии файлов.

Тесты используют Lua 5.2 и модели диска/сети. Проверяются скачивание с ошибкой,
повреждённый файл, частичная запись, восстановление, повторная установка,
сохранение данных, откат и обработка доступных синхронных OC-методов.
Установка на реальном McSkill ещё требует запуска пользователем.

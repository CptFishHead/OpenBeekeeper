# OpenBeekeeper 🐝

Помощник пчеловода для OpenComputers, Forestry и Gendustry на McSkill HiTech 1.12.2.

Цель проекта — собрать в выделенной МЭ-подсети образцы генов всех доступных видов
пчёл. Рабочие признаки применяются из пользовательского шаблона через генетический
импринтер; собирать все варианты остальных генов не требуется.

**Версия 0.4.0: установка/обновление, обнаружение нескольких транспозеров, чтение МЭ,
сохранение ролей сетей и цветной просмотр коллекции.**
Автоматический перенос, сбор генов и интерактивный граф
ещё не реализованы. Код проверяется на Lua 5.2 с моделями компонентов; проверка
новых МЭ-возможностей на сервере ещё нужна.

Архитектура: [три подсети, несколько пасек, каталог и карта](docs/architecture.md).
Исследование файлов и байткода установленной сборки: [McSkill audit](docs/mcskill-audit.md).

## Проверенная установка

- OpenOS 1.8.10, компьютер с интернет-картой.
- Транспозеры OpenComputers обнаруживаются автоматически, адреса не зашиты в код.
- Положение пасек, мутатронов и инвентарей определяется опросом всех шести граней.
- На тестовой установке доступны промышленная пасека (15 слотов), сундук пчеловода
  и обычный мутатрон. Сундук не является обязательной частью будущей МЭ-системы.
- Устройства касаются граней транспозера. Кабель соединяет транспозер с компьютером.
- На этом сервере для доступа понадобилось добавить `OpenComputers` в регион.

Номера сторон относятся к миру, а не к направлению взгляда игрока.

## Запуск

Установка одной командой в OpenOS:

```sh
wget -fq https://raw.githubusercontent.com/CptFishHead/OpenBeekeeper/main/install.lua /home/beekeeper-setup.lua && lua /home/beekeeper-setup.lua
```

После установки: `bees catalog`, `bees me`, `bees map`. Обслуживание:
`bees check`, `bees update`, `bees reinstall`, `bees rollback`.
Подробности и восстановление: [INSTALL.md](INSTALL.md).

Один раз назначьте роли по актуальным номерам из `bees me`. Порядок аргументов:
племенная, перекладная, архив. Например, если это сети №2, №3 и №1:

```sh
bees setup 2 3 1
bees roles
bees owned
```

После настройки `bees map` и `bees owned` сами читают племенную сеть и архив.
`owned` выводит только найденные пчёлы и образцы, `map` — также отсутствующие виды
живого каталога. Привязки сохраняются отдельно от программы, не зависят от порядка
списка и сохраняются при обновлении. После замены МЭ-компонента отсутствующая роль
блокируется до повторного `setup`; программа не выбирает случайную замену.
Три разные точки ещё не доказывают три разные сети: физическую изоляцию проверяет игрок.

### Отдельный диагностический файл

Скопируйте `openbeekeeper.lua` на игровой компьютер и запустите из OpenOS:

```sh
lua openbeekeeper.lua
```

Программа читает все транспозеры, соседние инвентари и доступные ID видов.
Она ничего не перемещает. Число транспозеров и пасек не ограничено константой.
Для просмотра доступных точек доступа к МЭ:

```sh
lua openbeekeeper.lua me
```

Несколько точек могут относиться к одной сети. Номера временные, это не постоянные
роли. Подключите адаптер OC к МЭ-интерфейсу небольшой тестовой сети и положите в
неё пчелу и заполненный образец гена. Например, для первой точки:

```sh
lua openbeekeeper.lua probe 1
```

Между запросами содержимого МЭ выдерживается минимум **30 секунд** на одном
компьютере: интервал общий для всех подсетей, `probe` и `map`. Время последнего
запроса сохраняется в `/home/.openbeekeeper-data/me-last-read`, поэтому отдельные
запуски команд тоже соблюдают паузу. Ошибочная попытка также учитывается.
Команда `me` лишь перечисляет компоненты и содержимое сетей не запрашивает.
Это интервал опроса; уже выполняющийся вызов OC он не прерывает.

Это покажет до трёх примеров полей пчёл/образцов. Нужна проверка, раскрывает ли
сервер точный ген через МЭ. Доступ `getItemsInNetwork` сам по себе не даёт
произвольного экспорта; драйвер переноса ещё предстоит проверить и реализовать.

Карта только локально видимых пчёл:

```sh
lua openbeekeeper.lua map
```

Карта с чтением племенной сети №1 и архива №3 (подставить номера из `me`):

```sh
lua openbeekeeper.lua map 1 3
```

Зелёный означает найденный образец вида: `G` — подтверждение по структурированному
NBT, `L` — точное сопоставление серверной английской подписи `Bee Sample - Species: ...`
с единственным UID в живом каталоге. `L` — свидетельство по подписи, **не проверка NBT**;
будущий исполнитель не должен расходовать предметы или применять шаблоны на этой основе.
Неизвестные/неоднозначные имена и другие хромосомы не помечаются как виды.
Голубой означает живую пчелу без найденного образца. Сейчас это текстовый просмотр с
небольшой демонстрационной ветвью, а не полный серверный граф скрещиваний.
Декодер принимает только структурированные поля `tag`/`nbt` с известной схемой
Gendustry; другие форматы остаются неизвестными до проверки на сервере.

Для получения живого каталога подключите адаптер OC к **обычной пасеке Forestry**:

```sh
lua openbeekeeper.lua catalog
```

Команда обнаружит API по методам, покажет число видов/мутаций и примеры данных.
В установленном OC `listAllSpecies` возвращает результаты зарегистрированных
мутаций, а не полный реестр видов. Дикие виды могут отсутствовать; рецепты содержат
локализованные имена, требующие однозначного сопоставления с UID. При наличии API
карта дополняется видами из живого каталога. Данные клиента не заменяют проверку
доступности мутаций на сервере.

Скачать файл в новый локальный файл, чтобы не перезаписывать текущий:

```sh
wget https://raw.githubusercontent.com/CptFishHead/OpenBeekeeper/main/openbeekeeper.lua beekeeper02.lua
lua beekeeper02.lua me
```

## Проверки разработки

```sh
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
```

Тесты выполняют скрипт в Lua 5.2 с моделями компонентов OC. Это не заменяет
проверку на сервере с его версиями и настройками модов.

## Слоты устройств

| Устройство | Слоты | Назначение |
|---|---|---|
| Обычный мутатрон | 1 | Принцесса |
| Обычный мутатрон | 2 | Трутень |
| Обычный мутатрон | 3 | Матка, результат |
| Обычный мутатрон | 4 | Genetics Labware |
| Промышленная пасека | 1 | Принцесса или матка |
| Промышленная пасека | 2 | Трутень |
| Промышленная пасека | 3–6 | Улучшения — не извлекать при сборе |
| Промышленная пасека | 7–15 | Выход, диапазон требует дальнейшей проверки |

В наблюдавшемся цикле потомство находилось в слотах 8 и 9, соты — в 7.
Программа разведения должна определять тип предмета, а не рассчитывать на постоянный
номер выходного слота.

## Что подтверждено в игре

- Чтение инвентарей транспозером после настройки региона.
- Перенос принцессы в слот 1 пасеки и трутня в слот 2.
- Обычный мутатрон сам запускает процесс при наличии подходящей пары и ресурсов.
- Cultivated Princess + Common Drone дали Diligent Queen.
- Перенос этой матки из слота 3 мутатрона в слот 1 пасеки.
- После её цикла получены Diligent Princess и два Diligent Drone.
- Через адаптер у пчелы читался `individual.ident`. У непроанализированных пчёл
  полные активные и неактивные гены в показанном выводе отсутствовали.

У доступного через адаптер продвинутого мутатрона не обнаружена команда выбора
мутации: доступны методы энергии и инвентаря. Поэтому проект ориентируется на
обычный мутатрон, с проверкой фактического результата каждого скрещивания.

## Следующие этапы

1. Проверить поля пчёл и Gene Sample через МЭ и экспорт точного NBT-варианта.
2. Дополнить сохранённые роли сетей настройкой модулей пасек и маршрутов экспорта.
3. Добавить каталог генов, журнал и резервирование материалов заданий.
4. Реализовать независимые исполнители пасек, мутатронов и пробоотборников.
   Добавить импринтер с постоянным рабочим шаблоном без гена вида, проверкой
   сохранения вида и защитой последней принцессы.
5. Добавить проверенный серверный каталог и планировщик сбора генов.
6. Расширить цветной просмотр до интерактивной карты с поиском и карточками видов.

Наличие хотя бы одного вида ещё не означает сохранённую линию. Для продолжения
нужны воспроизводимые родители и запас трутней. Мутатрон расходует принцессу;
использовать последнюю принцессу исходной линии без стратегии восстановления нельзя.
Полный список доступных на сервере видов и рецептов пока не собран.

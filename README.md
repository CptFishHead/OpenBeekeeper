# OpenBeekeeper 🐝

Помощник пчеловода для OpenComputers, Forestry и Gendustry на McSkill HiTech 1.12.2.

Цель проекта — собрать в МЭ-системе образцы генов всех доступных видов
пчёл. Рабочие признаки применяются из пользовательского шаблона через генетический
импринтер; собирать все варианты остальных генов не требуется.

**Версия 0.10.5: тайм-аут доставки пчелы переводит её задание в ожидание,
а не останавливает всю фабрику.** Запрос интерфейса снимается, точная ссылка
сохраняется; незагруженная машина освобождается для других заданий. Повторная
попытка — не раньше чем через 20 секунд. Остальные задания
и пасеки продолжают обслуживаться. Для ручного старта заново после очистки
механизмов сохранён `bees auto reset empty`.
Привязки модулей, климат и роли МЭ сохраняются. Подробнее: [состояние и восстановление](docs/automation.md#намеренный-старт-заново).

Из версии 0.10.1 сохранены привязка модулей при лишних МЭ-интерфейсах и
восстановление вымерших линий с уже сохранённым образцом вида.
`bind` пропускает занятые и посторонние интерфейсы, проверяет кандидатов маркером
и сохраняет предыдущую полную карту при неполной привязке. Посторонние
транспозеры без пчелиных машин не мешают обнаружению. Если живых пчёл вида больше
нет, автоцикл снова допускает его мутацию и восстанавливает запас 32 трутней
без повторного пробоотбора.

Сохраняются параллельная подготовка родителей, очередь по шести входам
анализатора и отдельные климатические зоны для новых маток из версии 0.10.0.
Пасеки размножения используются только для пар после анализатора и импринтера;
матки из мутатрона сначала анализируются и направляются в совместимую биомную зону.
Нет ограничения одним заданием на вид: учитываются доступные родители и
ожидаемое потомство. Шанс образца, постоянный запас 32, рулетка мутатрона и
разрешение всех условных рецептов включено. Справочник климата извлечён из клиента;
серверные отличия требуют явной корректировки. Новый режим проверен моделями,
а не полным прогоном на живом сервере.

Архитектура: [одна МЭ, рабочие сундуки и несколько пасек](docs/architecture.md).
Исследование файлов и байткода установленной сборки: [McSkill audit](docs/mcskill-audit.md).
Подключение и команды: [привязка модулей](docs/module-binding.md).

## Автоматический запуск

```sh
bees update
bees bind
bees zones breeding native
bees zones
bees auto
```

`bees run` теперь является синонимом `bees auto`: прежний режим с подачей
необработанных родителей больше не запускается. Для каждой принцессы и каждого
трутня, который пойдёт в спаривание, порядок — **анализатор → импринтер → пасека
или обычный мутатрон**. Родительские особи запрашиваются по точным копиям NBT;
обе обработанные пчелы не заменяются первой попавшейся парой с тем же названием.
Матка, уже созданная мутатроном, проходит анализатор и заканчивает первый цикл
в подходящей климатической пасеке; импринтер не принимает маток. Всё её потомство перед последующим спариванием
снова проходит анализатор и импринтер.

Четыре исходных модуля без эмуляторов назначаются командой `zones breeding native`
(для текущей установки ожидается 16 пасек). Пасеки с эмуляторами автоматически
становятся инкубационными зонами. Подробнее: [зоны и климат](docs/climate.md).
Все подробности, расходники и восстановление: [автоцикл](docs/automation.md).
Остановка — `Ctrl+C`, продолжение — `bees auto` или `bees auto resume`.
Сохранённые задания: `bees auto status`. Для намеренного старта заново с пустыми механизмами —
`bees auto reset`; после успешного сброса запускать `bees auto`. Компьютер и механизмы должны оставаться
в загруженных чанках и иметь питание. Автозапуск после перезагрузки не добавляется.

## План коллекции

`bees plan` читает общую сеть, выбранную через `bees setup`, и считает принцесс,
трутней и маток отдельно для каждого вида. Используется тот же кэш на 20 секунд,
что и у `owned`: второй снимок для образцов не запрашивается. Пчёлы внутри
механизмов в складские количества не входят.

Цель запаса — **32 трутня каждого вида в МЭ**, включая виды с уже собранным
образцом. Ниже цели план предлагает размножение, завершение цикла матки или
сообщает об отсутствующем родителе. В пробоотборник предлагается только излишек
сверх 32: при 32 донора нет, при 33 доступен один. Принцессы и матки не предлагаются
как доноры. Далее выводятся пары из живого серверного каталога,
у которых нет живых пчёл результата в сети. Если образец уже сохранён, такая пара
помечается как восстановление линии; образец не заменяет запас 32 трутней. Рецепты со специальными условиями включены; их подписи показываются без утверждения, что условия выполнены. Использование последней принцессы
или запаса из 32 трутней помечается для проверки. Это не проверка
совместимости условий с конкретной машиной и не выбор результата мутатрона.

`KEEP` означает структурно подтверждённый образец вида; `REVIEW` — лишь совпадение
названия образца. Случайный хромосомный результат пробоотборника не гарантирует
ген вида. План ничего не перемещает и не запускает задания; для работы есть
отдельная команда `auto`. План показывает доступный склад, а не чистоту генома:
для гибридов ID активного вида недостаточно, чтобы гарантировать вид потомства.
Для будущей стадии пробоотбора принят сообщённый игроком шанс 7,7% на нужный ген
с трутня: 38 доноров сверх постоянного запаса дают не меньше 95% вероятности
хотя бы одного успеха при независимых попытках, но не гарантию.

## Проверенная установка

- OpenOS 1.8.10, компьютер с интернет-картой.
- Транспозеры OpenComputers обнаруживаются автоматически, адреса не зашиты в код.
- Положение пасек, мутатронов и инвентарей определяется опросом всех шести граней.
- На тестовой установке доступны промышленная пасека (15 слотов), сундук пчеловода
  и обычный мутатрон. Сундук не является обязательной частью будущей МЭ-системы.
- Устройства касаются граней транспозера. Кабель соединяет транспозер с компьютером.
- На этом сервере для доступа понадобилось добавить `OpenComputers` в регион.

Номера сторон относятся к миру, а не к направлению взгляда игрока.

## Запуск

Установка одной командой в OpenOS:

```sh
wget -fq https://raw.githubusercontent.com/CptFishHead/OpenBeekeeper/main/install.lua /home/beekeeper-setup.lua && lua /home/beekeeper-setup.lua
```

После установки: `bees catalog`, `bees me`, `bees map`. Обслуживание:
`bees check`, `bees update`, `bees reinstall`, `bees rollback`.
Подробности и восстановление: [INSTALL.md](INSTALL.md).

Рекомендуемая схема — одна МЭ-сеть для пчёл и образцов и отдельный МЭ-интерфейс
возле каждого транспозера. Один транспозер обслуживает несколько пасек либо
отдельный механизм. Сундук пчеловода и перекладная МЭ-сеть не обязательны.
Подключите один доступный для OC контроллер/интерфейс общей сети и
выберите его актуальный номер из `bees me`, например №1:

```sh
bees setup 1
bees roles
bees owned
```

После настройки `bees map` и `bees owned` одним запросом читают общую сеть
и учитывают в одном снимке живых пчёл и образцы видов.
`owned` выводит только найденные пчёлы и образцы, `map` — также отсутствующие виды
живого каталога. Привязки сохраняются отдельно от программы, не зависят от порядка
списка и сохраняются при обновлении. После замены МЭ-компонента отсутствующая роль
блокируется до повторного `setup`; программа не выбирает случайную замену.
Несколько контроллеров одной сети не требуют отдельных запросов — выберите один.
`bees me` также отдельно показывает экспортные шины (`X1`, `X2`, ...) и базы
данных OC (`D1`, ...). Они не обязаны иметь `getItemsInNetwork`, поэтому не смешиваются
с номерами точек чтения. Проверка не меняет фильтры и не выполняет экспорт.
Адаптер для шины должен касаться блока МЭ-кабеля, на котором установлена шина;
видимая выступающая модель шины сама по себе не является отдельным блоком.
Старые раздельные роли продолжают работать. Для перехода после объединения сетей
выполните `bees me` и `bees setup <номер общей сети>`; это сохраняет привязку,
но не перемещает предметы и не соединяет сети физически.

### Отдельный диагностический файл

Скопируйте `openbeekeeper.lua` на игровой компьютер и запустите из OpenOS:

```sh
lua openbeekeeper.lua
```

Программа читает все транспозеры, соседние инвентари и доступные ID видов.
По умолчанию она ничего не перемещает. Число транспозеров и пасек не ограничено константой.
Для просмотра доступных точек доступа к МЭ:

```sh
lua openbeekeeper.lua me
```

Несколько точек могут относиться к одной сети. Номера временные, это не постоянные
роли. Подключите адаптер OC к МЭ-интерфейсу небольшой тестовой сети и положите в
неё пчелу и заполненный образец гена. Например, для первой точки:

```sh
lua openbeekeeper.lua probe 1
```

Между запросами содержимого МЭ выдерживается минимум **20 секунд** на одном
компьютере. Успешный снимок пчёл и образцов сохраняется на диск: повторные `probe`,
`owned` и `map` в пределах 20 секунд читают его **без нового запроса и ожидания**.
Возраст снимка показывается. Истёкший или повреждённый кэш обновляется, ошибки не
выдаются за свежие данные. При обращении к другой сети действует общий интервал.
Время последней попытки хранится в `/home/.openbeekeeper-data/me-last-read`,
снимки — в `me-cache-*`; отдельные запуски команд разделяют кэш и ограничение.
Сохраняется лишь подмножество предметов пчёл/образцов, не весь склад базы.
Команда `me` лишь перечисляет компоненты и содержимое сетей не запрашивает.
Это интервал опроса; уже выполняющийся вызов OC он не прерывает.

Это покажет до трёх примеров полей пчёл/образцов. Нужна проверка, раскрывает ли
сервер точный ген через МЭ. Доступ `getItemsInNetwork` сам по себе не даёт
произвольного экспорта. Ручная проверка подтвердила подачу через конфигурацию
МЭ-интерфейса и возврат выходных предметов транспозером. Команда `bind`
определяет маршруты, а `auto` выполняет обработку и селекцию.

Карта только локально видимых пчёл:

```sh
lua openbeekeeper.lua map
```

При старой раздельной схеме поддерживается явное чтение племенной сети №1 и
архива №3 (номера из `me`):

```sh
lua openbeekeeper.lua map 1 3
```

Зелёный означает найденный образец вида: `G` — подтверждение по структурированному
NBT, `L` — точное сопоставление серверной английской подписи `Bee Sample - Species: ...`
с единственным UID в живом каталоге. `L` — свидетельство по подписи, **не проверка NBT**;
автоцикл использует её только для прекращения лишнего пробоотбора/работы, а не
для выбора генов шаблона или подтверждения NBT обрабатываемой пчелы.
Неизвестные/неоднозначные имена и другие хромосомы не помечаются как виды.
Голубой означает живую пчелу без найденного образца. Сейчас это текстовый просмотр с
небольшой демонстрационной ветвью, а не полный серверный граф скрещиваний.
Декодер принимает только структурированные поля `tag`/`nbt` с известной схемой
Gendustry; другие форматы остаются неизвестными до проверки на сервере.

Для получения живого каталога подключите адаптер OC к **обычной пасеке Forestry**:

```sh
lua openbeekeeper.lua catalog
```

Команда обнаружит API по методам, покажет число видов/мутаций и примеры данных.
В установленном OC `listAllSpecies` возвращает результаты зарегистрированных
мутаций, а не полный реестр видов. Дикие виды могут отсутствовать; рецепты содержат
локализованные имена, требующие однозначного сопоставления с UID. При наличии API
карта дополняется видами из живого каталога. Данные клиента не заменяют проверку
доступности мутаций на сервере.

Скачать файл в новый локальный файл, чтобы не перезаписывать текущий:

```sh
wget https://raw.githubusercontent.com/CptFishHead/OpenBeekeeper/main/openbeekeeper.lua beekeeper02.lua
lua beekeeper02.lua me
```

## Проверки разработки

```sh
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
```

Тесты выполняют скрипт в Lua 5.2 с моделями компонентов OC. Это не заменяет
проверку на сервере с его версиями и настройками модов.

## Слоты устройств

| Устройство | Слоты | Назначение |
|---|---|---|
| Обычный мутатрон | 1 | Принцесса |
| Обычный мутатрон | 2 | Трутень |
| Обычный мутатрон | 3 | Матка, результат |
| Обычный мутатрон | 4 | Genetics Labware |
| Промышленная пасека | 1 | Принцесса или матка |
| Промышленная пасека | 2 | Трутень |
| Промышленная пасека | 3–6 | Улучшения — не извлекать при сборе |
| Промышленная пасека | 7–15 | Выход, диапазон требует дальнейшей проверки |

В наблюдавшемся цикле потомство находилось в слотах 8 и 9, соты — в 7.
Программа разведения должна определять тип предмета, а не рассчитывать на постоянный
номер выходного слота.

## Что подтверждено в игре

- Чтение инвентарей транспозером после настройки региона.
- Перенос принцессы в слот 1 пасеки и трутня в слот 2.
- Обычный мутатрон сам запускает процесс при наличии подходящей пары и ресурсов.
- Cultivated Princess + Common Drone дали Diligent Queen.
- Перенос этой матки из слота 3 мутатрона в слот 1 пасеки.
- После её цикла получены Diligent Princess и два Diligent Drone.
- Через адаптер у пчелы читался `individual.ident`. У непроанализированных пчёл
  полные активные и неактивные гены в показанном выводе отсутствовали.

У доступного через адаптер продвинутого мутатрона не обнаружена команда выбора
мутации: доступны методы энергии и инвентаря. Поэтому проект ориентируется на
обычный мутатрон, с проверкой фактического результата каждого скрещивания.

## Следующие этапы

1. Проверить поля пчёл и Gene Sample через МЭ и экспорт точного NBT-варианта.
2. Дополнить сохранённые роли сетей настройкой модулей пасек и маршрутов экспорта.
3. Добавить каталог генов, журнал и резервирование материалов заданий.
4. Реализовать независимые исполнители пасек, мутатронов и пробоотборников.
   Добавить импринтер с постоянным рабочим шаблоном без гена вида, проверкой
   сохранения вида и защитой последней принцессы.
5. Добавить проверенный серверный каталог и планировщик сбора генов.
6. Расширить цветной просмотр до интерактивной карты с поиском и карточками видов.

Наличие хотя бы одного вида ещё не означает сохранённую линию. Для продолжения
нужны воспроизводимые родители и запас трутней. Мутатрон расходует принцессу;
использовать последнюю принцессу исходной линии без стратегии восстановления нельзя.
Полный список доступных на сервере видов и рецептов пока не собран.

## Исправление привязки к общей МЭ-сети

`bees bind` допускает лишние МЭ-интерфейсы: пропускает настроенные, проверяет
остальные маркером и останавливается после привязки всех рабочих модулей.
При неполной привязке предыдущая карта сохраняется. Подробности —
[привязка модулей](docs/module-binding.md).
